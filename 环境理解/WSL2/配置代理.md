## 一、查看当前通信方式

这里的“通信方式”主要看三件事：

第一，WSL2 当前访问 Windows 主机的网关地址是什么。

执行：

```bash
ip route | grep default
```

可能输出：

```text
default via 172.24.128.1 dev eth0
```

其中：

```text
172.24.128.1
```

就是 WSL2 访问 Windows 主机的地址。你的代理软件运行在 Windows 上，所以 WSL2 要通过这个地址访问 Windows 代理端口。

也可以直接提取网关 IP：

```bash
ip route | awk '/default/ {print $3}'
```

也可以输入
```shell
 ipconfig.exe | iconv -f gbk -t utf-8 | grep -A 10 "WSL"
```
对应输出：
```shell
以太网适配器 vEthernet (WSL (Hyper-V firewall)):

   连接特定的 DNS 后缀 . . . . . . . :
   本地链接 IPv6 地址. . . . . . . . : fe80::10e2:dfb7:30fc:f6b%55
   IPv4 地址 . . . . . . . . . . . . : 172.24.128.1
   子网掩码  . . . . . . . . . . . . : 255.255.240.0
   默认网关. . . . . . . . . . . . . :
```

---

第二，查看当前 WSL2 是否已经配置代理环境变量。

执行：

```bash
env | grep -i proxy
```

如果没有输出，说明当前 shell 环境没有代理变量。

如果已经配置成功，应该看到类似：

```text
HTTP_PROXY=http://172.24.128.1:7897
HTTPS_PROXY=http://172.24.128.1:7897
ALL_PROXY=socks5h://172.24.128.1:7897
http_proxy=http://172.24.128.1:7897
https_proxy=http://172.24.128.1:7897
all_proxy=socks5h://172.24.128.1:7897
```

解释一下：

`HTTP_PROXY` 用于 HTTP 请求，`HTTPS_PROXY` 用于 HTTPS 请求，`ALL_PROXY` 是通用代理变量。大小写都配置，是为了兼容不同工具。有些工具读大写，有些工具读小写。

---

第三，查看 Git 当前使用的是 HTTPS 还是 SSH。

进入项目目录后执行：

```bash
git remote -v
```

如果看到：

```text
origin  https://github.com/mesiphy/quant-v2.git
```

说明 Git 使用 HTTPS 通信。

如果看到：

```text
origin  git@github.com:mesiphy/quant-v2.git
```

说明 Git 使用 SSH 通信。

这一步很重要，因为 HTTPS 和 SSH 的代理配置方式不同。

## 二、配置代理：临时方法

临时方法只对当前终端窗口有效。关闭当前 WSL2 终端后会失效。适合测试。

你的代理软件混合端口是 `7897`，WSL2 网关是 `172.24.128.1`，所以执行：

```bash
export HTTP_PROXY=http://172.24.128.1:7897
export HTTPS_PROXY=http://172.24.128.1:7897
export ALL_PROXY=socks5h://172.24.128.1:7897

export http_proxy=$HTTP_PROXY
export https_proxy=$HTTPS_PROXY
export all_proxy=$ALL_PROXY
```

解释：

```text
HTTP_PROXY=http://172.24.128.1:7897
表示 HTTP 请求走 Windows 代理软件的 7897 端口。

HTTPS_PROXY=http://172.24.128.1:7897
表示 HTTPS 请求也走 Windows 代理软件的 7897 端口。

ALL_PROXY=socks5h://172.24.128.1:7897
表示支持 SOCKS5 的工具可以通过这个代理出去。
socks5h 中的 h 表示 DNS 解析也交给代理处理。
```

设置完后立即检查：

```bash
env | grep -i proxy
```

然后测试访问 GitHub：

```bash
curl -I https://github.com
```

或者显式指定代理测试：

```bash
curl -vI -x http://172.24.128.1:7897 https://github.com
```

如果看到：

```text
HTTP/1.1 200 Connection established
HTTP/2 200
```

说明代理通信正常。

测试 OpenAI API：

```bash
curl -vI -x http://172.24.128.1:7897 https://api.openai.com
```

如果看到：

```text
CONNECT api.openai.com:443 HTTP/1.1
HTTP/1.1 200 Connection established
CONNECT tunnel established
```

说明 WSL2 确实通过 Windows 代理访问了 `api.openai.com`。

## 三、配置代理：长期方法

长期方法是把代理环境变量写入 `~/.bashrc`，以后每次打开 WSL2 终端都会自动生效。

执行：

```bash
cat >> ~/.bashrc <<'EOF'

# WSL2 -> Windows proxy
export HTTP_PROXY=http://172.24.128.1:7897
export HTTPS_PROXY=http://172.24.128.1:7897
export ALL_PROXY=socks5h://172.24.128.1:7897

export http_proxy=$HTTP_PROXY
export https_proxy=$HTTPS_PROXY
export all_proxy=$ALL_PROXY
EOF
```

让配置立即生效：

```bash
source ~/.bashrc
```

检查：

```bash
env | grep -i proxy
```

如果能看到代理变量，说明长期配置已经对当前 shell 生效。

如果你使用的是 zsh，而不是 bash，则应该写入：

```bash
cat >> ~/.zshrc <<'EOF'

# WSL2 -> Windows proxy
export HTTP_PROXY=http://172.24.128.1:7897
export HTTPS_PROXY=http://172.24.128.1:7897
export ALL_PROXY=socks5h://172.24.128.1:7897

export http_proxy=$HTTP_PROXY
export https_proxy=$HTTPS_PROXY
export all_proxy=$ALL_PROXY
EOF

source ~/.zshrc
```

可以用下面命令查看当前 shell：

```bash
echo $SHELL
```

如果输出：

```text
/bin/bash
```

就改 `~/.bashrc`。

如果输出：

```text
/bin/zsh
```

就改 `~/.zshrc`。

## 四、单独配置 Git HTTPS 代理

环境变量可以影响很多命令行工具，但 Git 最稳的方式是单独配置 Git 代理。

如果你的 `git remote -v` 是 HTTPS 地址：

```text
https://github.com/mesiphy/quant-v2.git
```

执行：

```bash
git config --global http.proxy http://172.24.128.1:7897
git config --global https.proxy http://172.24.128.1:7897
```

检查 Git 代理配置：

```bash
git config --global --get http.proxy
git config --global --get https.proxy
```

理想输出：

```text
http://172.24.128.1:7897
http://172.24.128.1:7897
```

测试 Git 是否能访问 GitHub：

```bash
git ls-remote https://github.com/mesiphy/quant-v2.git
```

如果能看到 `HEAD`、`refs/heads/main`、`refs/heads/...` 等内容，说明 Git HTTPS 通信已经正常。

之后可以执行：

```bash
git pull
```

或者：

```bash
git clone https://github.com/mesiphy/quant-v2.git
```

## 五、如果 Git 使用 SSH 通信

如果你的 remote 是：

```text
git@github.com:mesiphy/quant-v2.git
```

那么 Git 的 `http.proxy` / `https.proxy` 不会对 SSH 生效，需要配置 SSH。

先检查当前 SSH 配置：

```bash
ssh -G github.com | grep -E "hostname|user|port|proxycommand"
```

如果没有 `proxycommand`，说明 SSH 当前没有走代理。

编辑 SSH 配置：

```bash
nano ~/.ssh/config
```

写入：

```sshconfig
Host github.com
  HostName github.com
  User git
  Port 22
  ProxyCommand nc -X 5 -x 172.24.128.1:7897 %h %p
```

保存后设置权限：

```bash
chmod 600 ~/.ssh/config
```

再次检查：

```bash
ssh -G github.com | grep -E "hostname|user|port|proxycommand"
```

理想输出应该包含：

```text
user git
hostname github.com
port 22
proxycommand nc -X 5 -x 172.24.128.1:7897 %h %p
```

测试 SSH：

```bash
ssh -T git@github.com
```

如果看到：

```text
Hi mesiphy! You've successfully authenticated, but GitHub does not provide shell access.
```

说明 SSH 通信已经正常。

## 六、检查代理是否配置成功

建议按这个顺序检查。

第一，检查环境变量：

```bash
env | grep -i proxy
```

成功标志：能看到 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 等变量。

第二，检查代理端口是否能访问：

```bash
curl -vI -x http://172.24.128.1:7897 https://github.com
```

成功标志：

```text
Trying 172.24.128.1:7897
CONNECT github.com:443 HTTP/1.1
HTTP/1.1 200 Connection established
HTTP/2 200
```

第三，检查 OpenAI API 是否能通过代理访问：

```bash
curl -vI -x http://172.24.128.1:7897 https://api.openai.com
```

成功标志：

```text
CONNECT api.openai.com:443 HTTP/1.1
HTTP/1.1 200 Connection established
CONNECT tunnel established
```

即使最后返回 `HTTP/2 421`，也不代表代理失败。关键是前面的 `200 Connection established` 和 TLS 握手成功。

第四，如果使用 Git HTTPS，检查：

```bash
git config --global --get http.proxy
git config --global --get https.proxy
git ls-remote https://github.com/mesiphy/quant-v2.git
```

成功标志：`git ls-remote` 能输出远程分支和 commit hash。

第五，如果使用 Git SSH，检查：

```bash
ssh -G github.com | grep -E "hostname|user|port|proxycommand"
ssh -T git@github.com
```

成功标志：`ssh -G` 里有 `proxycommand`，`ssh -T` 能认证成功。
